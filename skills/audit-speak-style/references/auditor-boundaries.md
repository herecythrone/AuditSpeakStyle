# 审计身份、证据与结论适配

本文件把上游来源限定、工作与意见分离、特殊事项保留等机制改编为审计写作边界；它不是准则库，也不判断用户实际项目是否符合准则。以下微例均为**虚构教学案例**。B01—B10用于测试和溯源。

## B01｜先确定谁在说话

公司说明保留公司身份；管理层解释标明说明人；项目组记录按真实执行主体写；事务所对外文件才能在适当上下文用“本所”。不统一使用“我们”，也不统一删除主语。助手是在整理文字，不是执行核查、签字或出具意见的会计师。

对多人、多来源材料分别表述。不要把“公司称已收到货款”改成“我们确认已收到货款”。无署名信息时不自行填事务所名、签字人、日期或执业资质。

## B02｜执行状态不能靠文字生成

询问不等于验证；获取不等于检查；阅读说明不等于完成核查；核查要点不等于已执行程序；计划表勾选也需明确其含义。只将材料明确已执行的动作写成已执行。没有提供执行信息时，不写已执行，也不擅自写未执行。

“拟下周核对”“已取得尚未核对”“核对中”“已核对一致”各有不同含义。程序结果若只支持金额比较，不自动加数量、日期或业务真实性也一致。禁止自动添加函证、访谈、穿行测试、重新计算等程序来装饰说明。

资料沟通也遵守本条：逐项区分拟请求、已请求、已催办、已收到、已核查。“希望客户提供”“请帮我写一条索取资料的消息”是意图或当前请求，不是此前已要求、已催请的记录。已请求不代表已催办；已催办不代表已收到；已收到不代表已核查；已核查也不自动代表结果一致。收到或核查的事实不能反推此前存在请求或催办，次数、日期和结果均须另有依据。

按主体、资料对象及范围分别保留状态，不把一项资料的完成状态套给其他资料。起草客户消息可直接写“请提供……”，状态记录可写“拟请客户提供……”；仅生成消息不等于已发送。已明确发生的请求、催办、收件或核查也不得改回拟办；未说明的状态保持未知，不补成已做或未做。

## B03｜范围与抽样结果随句保留

样本数、选择范围、覆盖期间、核对字段及例外不能在总结时扩大。30笔采购样本数量一致，不代表全部采购准确；部分回函一致，不代表全部余额真实完整；未回函仅是回函状态，不自动证明余额虚假或不存在。

若用户已给出依据充分的总体判断，可以忠实表达该判断；但不能由写作技能从局部程序结果自行推导总体保证。没有必要在每句重复范围，前提是该范围在段内明确覆盖且摘引后仍不易误读。

## B04｜金额、差异、错报与重要性分别判断

金额小不自动推出风险低、无需程序、对报表影响有限或不重大。差异可能来自口径、时间或错误；未确认前写差异，不写多记、少计或错报。已被确认是错报的，不应反过来含糊地叫“有关情况”。

拟不调整、已不调整、未调整错报与不重大不能互换。明显微小也不能仅凭语感替代不重大。若用户提供已完成的专业评估及结论，就保留其对象、依据和状态，不强制回退成“不清楚”。不能仅凭对话中一个金额替用户作专业评估。

## B05｜不同结论不是可升级的阶梯

程序结果、资料事实、审计判断、法律意见是不同性质的表达。它们不存在通过换词逐级增强的通道；上游高/中/低风险标签也不得自动映射成审计意见类型。

| 原有含义 | 不能自动改成 |
|---|---|
| 未发现差异 | 不存在任何差异 |
| 未发现异常 | 未发现重大异常（新增了程度门槛） |
| 未发现重大影响 | 没有任何影响 |
| 拟不调整 | 已认定不重大 |
| 风险表标记“低” | 可以发表无保留意见 |
| 合同条款与订单一致 | 合同合法有效 |

必要的纠错不等于无条件保持原结论：原文确与给定事实冲突时应纠正，并作一句实质提示；事实不足时不另造一种更弱但同样无依据的结论。

## B06｜法律事项可描述、可转述，不能换皮

允许准确写法律事项的已知事实，准确转述有来源的专业意见，并表达已经有依据的审计影响判断。禁止把“合法合规、不存在法律风险”简单换成“未对整体变更/发行上市构成重大不利影响”或“对财务报表影响有限”。对象改了不等于依据补齐。

若仅知收到行政处理通知，就写收到及给定的处理状态；没有法律性质、财务影响分析时不能代填。已给定律师针对某许可、截至某日的意见，应保留该事项、日期和限制，不扩展成公司全面合规。

“除某事项外……”同样含有对其余范围的判断；不能仅知道一个例外，就自动对其余一切作肯定结论。

## B07｜规范表述不当作风格瑕疵

用户明确适用的正式审计报告模板、签字责任、保证程度、意见类型和其他专业固定表述，不能仅凭更流畅、更简短或更肯定来改写。例如不把“合理保证”改成“绝对保证”，不任意删“在所有重大方面”。

没有取得适用模板时不要生成声称可签发的报告；可处理不改变专业含义的局部语句，并提示涉及专业判断或模板核验的部分。上游法律意见书结构不是审计报告格式依据。

## B08｜换载体不隐去未决问题

底稿可以直说“尚待核对”“理由待复核”；正式说明把对象、期限和当前状态交代完整，但不能把“尚有2笔未完成”改成“总体核查已完成”。已知缺口应随正文保留，不只藏在给项目组的附注里。

表格字段缺失、Memo不符合格式、暂缺附件或重组章节，均不使已知问题消失。只对有依据的部分成文，其余说明限制或待补资料，不能以“格式不合格”作为静默删除问题的理由。

## B09｜数字、集合与条件是内容，不是装饰

复查金额单位、方向、分子分母、期间/时点、约/至少/不超过、拟/已/暂未。列举中的“等”“包括但不限于”代表开放范围，不可删成仅有列示项目；也不能反过来给穷尽清单加“等”。

期限与触发条件一并保留。公司“收到资料且审核完成后安排付款”不能变成“收到资料就付款”；用户没有承诺出报告时，不为了沟通圆润加“资料齐即可出具”。

## B10｜缺口和来源纪律

只基于用户提供或本次确实取得的内容写作。资料未说明原因，就不补原因；资料未说明核查状态，就不补已核查或未核查。关键身份不清、两个已给数值冲突时，分别列明来源，指出需要确认什么；仍可先完成无冲突部分。

输出占位只用于真实缺项，标为“〔待确认：具体问题〕”，不能让虚构数字看似已填。正文与复核提醒分开，但正文自身不能含误导性确定结论。未经明确授权，不提取真实客户材料写入公开示例、长期记忆或仓库。

## 一个必须保留与一个可以直接写的对照

仅询问所得原因：“据财务负责人说明，差异源于统计截止日不同，该解释尚待验证。”

已有给定完成记录：“项目组已将12份回函所列余额与对应账面余额逐一核对，均一致。”

前者不是永远不肯定，后者不是对全部余额作保证；二者分别匹配已有依据。更多写法见 [style-principles.md](style-principles.md)。
