## 判分方法

先逐项提取输入和实际正文的“主体—对象/范围—动作—时态/条件—结果”，再对照每例验收项。任一 hard_failures 命中，或任一 must_preserve 实质丢失，该例失败。正文错误不能靠附注提醒抵消。允许等义表达；否定句或明确拒绝错误改写时出现“已催请”不自动失败，不采用关键词命中作为最终语义判定。

至少分别标记：execution_upgrade（无依据已做）、execution_downgrade（已做退为拟做/未做）、unknown_to_negative（未知变未做）、scope_or_actor_drift（范围/主体串用）、result_fabrication（编造结果）、omission（丢失必要事实）。一例可有多个标签，升级错误优先报告，不用文风评分抵消。

## 可复现验证

静态检查：

```bash
python scripts/validate.py
python -m unittest discover -s tests -p 'test_*.py' -v
python scripts/prepare_eval.py --out local-runs/action-state-candidate
python scripts/validate.py --check-manifest
```

这些命令只验证结构、用例字段/关联、无答案导出和文件完整性；模型调用数为零。

模型验证采用配对实验：

1. 固定同一模型的精确版本/快照、宿主版本、推理强度、采样参数、调用方式及其他系统指令。基线技能取上述提交，候选技能取本补丁提交；两组使用完全相同的 **56例输入**，不可把基线原有44例与候选56例直接比较。可先运行T45—T56快速排查，再运行完整56例。
2. 用 prepare_eval.py 导出候选包，复制一份作为基线包，仅将其中技能目录替换为基线提交的完整技能目录；输入和运行日志模板保持相同。模型只读取技能目录及单例输入，不得访问 cases.json、cases.md、本文及评分资料。两个导出包分别记录技能文件哈希。
3. 每个模型/技能版本/用例至少独立运行5次，每次新上下文，随机交错基线和候选顺序。T23—T25保留独立的隐式路由测试方法。采用导出器生成的 explicit-inputs（本次53例）和 implicit-routing-inputs（本次56例）。
4. 优先复测历史记录中的 Luna / Terra；若旧快照已不可用，记录不可复现，不以别名或当前模型冒充旧版。无技能基线可另设第三组，不能替代基线技能对候选技能的比较。
5. 保存模型原始输出、时间、配置、技能提交/哈希、用例ID、重复编号、错误及完整失败理由。记录中的原始输出不可填入参考答案；超时/调用异常单列，不计为通过。评审时隐藏技能版本，由人工逐义评判，分歧复核。
6. 按模型、技能版本、用例分别报告实际调用数、有效输出数、升级失败数和比例、其他硬失败数及两组差值；保留每个重复的结果，不能把一次成功说成稳定通过。候选验收目标：T45—T56所有有效输出无升级且无其他硬失败；原44例不得出现相对基线的新硬失败。未达到则继续修订；即使达到，也仅说明这些配置与样本内未观察到失败，不证明普遍改善。

历史 smoke test 只提供汇总观察，未附这六题的完整输入/原始输出；T50 是针对已记录错误类型新增的回归题，不宣称精确复现原题。
