# 行为验收与工具测试

本目录分三类资料，不能混称“测试通过”：

1. **工具测试**：`test_*.py`实际运行验证检查器、来源映射、打包及提示导出器。它们不调用模型，不评价中文质量。
2. **行为测试设计**：[cases.json](cases.json)与[cases.md](cases.md)包含44个完整输入、参考作答、应保留内容、硬性失败和规则关联。其中40例触发写作、3例不触发、1例混合任务。
3. **编写者自检**：[author-review.md](author-review.md)记录对参考答案逐义检查，不是独立运行，也不是由另一个模型评分。

## 独立行为验收方法

先固定模型、版本、宿主、是否显式加载和上下文，再给模型技能完整目录以及输入；不要给reference_answer、must_preserve或hard_failures。每例用干净上下文，不把前例答案带到后例。T23—T25用于隐式路由检查，不能先强制调用本Skill再据此判断“误触发”；T26只调用写作部分。

可用随包脚本导出不含答案的材料，输出目录须不存在：

```bash
python scripts/prepare_eval.py --out local-runs/blind-inputs
```

输出包括：自包含的技能目录、44个仅含编号/输入的JSONL请求、独立触发排除请求，以及空白运行记录模板。显式运行包只含触发或混合输入；隐式路由包包含全部输入但不把期望路由交给被测模型。导出完成只说明材料已准备，不表示任何模型已经运行。

保存实际输出与时间、模型/宿主版本、调用方式和异常。结果由未事先看参考答案的运行阶段产生；人工/独立评审再读取验收项。出现程序补造、范围扩大、来源改变、结论偷换、条件丢失等任一硬性失败即该例不合格；随后评价是否真正改善句段、数字和逻辑。不要用含关键字的正则替代语义判断，否定或指出错误时可能正好出现禁错词。

“未出现硬性失败”也不等于文风改善。对T27、T28、T33、T40、T43、T44，另看是否使具体信息更易理解；对T01、T07、T29、T41、T42，少改或不改可以是最佳输出。局部通过不得外推所有审计文本。

## 工具验证

```bash
python scripts/validate.py
python -m unittest discover -s tests -p 'test_*.py' -v
python scripts/validate.py --check-manifest
```

运行环境及实测边界见 [验证报告](../docs/validation-report.md)。运行记录放local-runs或仓库之外；不要将含真实项目内容的模型输出公开。上游规则的纠正理由见 [改编映射](../docs/adaptation-map.md)。
